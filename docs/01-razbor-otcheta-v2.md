# Разбор документа «ПГУ · Обязательный раздел портала — панель руководителя», версия 2 от 30.09.2026

Дата разбора: 30.09.2026. Проверялся файл `838ced9a-… .html` (825 КБ), полученный от заказчика.

## 1. Что это за файл технически

- Это «бандл»: одна HTML-страница, внутри которой в JSON-манифесте упакованы шрифты (Golos Text, JetBrains Mono, 10 файлов woff2) и библиотека графиков ECharts (1,1 МБ, gzip). При открытии загрузчик распаковывает всё в blob-URL и подменяет документ. Внешних запросов страница не делает, работает офлайн.
- Все числа на экране считаются из трёх встроенных массивов: `DATA` (радар, файлы, свежесть, подписи, решения, пробелы, план), `BROKEN` (17 дефектных ссылок ФГОС), `HTTPURLS` (109 ссылок по http). Логика рендера — 17 КБ кода на чистом JS, вывод пользовательских строк экранируется функцией `esc()`.
- Без JavaScript документ не читается вообще. Печать в PDF и архивирование «как есть» затруднены. Для официального оборота нужен второй формат вывода (PDF/DOCX + JSON).

## 4. Содержательные замечания

### 4.1. Оценки по «фронтам» назначены экспертно, а не вычислены
Значения радара (97, 60, 60, 55, 88, 70, 58, 75) не выводятся из данных ни одной формулой. Индекс 70 — среднее из восьми субъективных чисел с равными весами. Нарушение закона и «качество площадки» весят одинаково. Для системы, которая должна работать регулярно, каждый фронт обязан считаться из проверок с опубликованной формулой (см. модель в `02-model-sistemy-proverki.md`).

### 4.2. Недооценён сигнал безопасности
Пробел «внедрённый скрипт в поле адреса кафедры ИнОУП» помечен как «инфо · целостность данных». Скрипт в текстовом поле публичной страницы — это либо хранимая XSS-уязвимость, либо след компрометации CMS. Это надо разбирать как инцидент: кто и когда внёс, есть ли такие же поля в других записях, что в логах CMS. Приоритет должен быть «критично».

### 4.3. Безопасность и «взлом» в отчёте почти не покрыты
Из всей темы угроз есть только срок сертификата, срок домена и упоминание DDoS-Guard. Нет: заголовков безопасности (HSTS, CSP, X-Frame-Options), версии CMS и известных уязвимостей, инвентаризации поддоменов, проверок по чёрным спискам (Яндекс/Google Safe Browsing, VirusTotal), контроля подмены контента (дефейс), SPF/DKIM/DMARC для домена, открытых админ-панелей и бэкапов, доменов-двойников для фишинга.

### 4.4. Персональные данные не проверены
152-ФЗ упомянут один раз. Не проверены: наличие политики обработки ПДн (ч. 2 ст. 18.1), уведомление о cookie/метриках, иностранные счётчики и шрифты (трансграничная передача), формы обратной связи по https и с согласием, объём публикуемого реестра ППС (5431 запись) относительно требований п. 12 №1493, порядок авторизации пользователей (требования 149-ФЗ к авторизации только через российские сервисы).

### 4.5. Филиал на бесплатном хостинге
sfpgu.my1.ru — площадка uCoz со сторонней рекламой и вне контроля вуза. В отчёте это «факт · квартал». Это как минимум риск репутации и соответствия требованиям к хостингу (реестр хостинг-провайдеров по 149-ФЗ), к тому же на такой странице нельзя обеспечить требования №1493 и ПП №102.

### 4.6. Утверждения без данных внутри файла
«Дозаполнить 5 направлений без файла», «~11% адресов в выборке требуют проверки», «89 соглашений», «5431 ссылка», «502 на 27 поддоменах» — в реестре цифр либо отсутствуют, либо честно помечены как невоспроизводимые. Первые два пункта надо либо подкрепить списками, либо снять.

### 4.7. Замороженная дата
KPI «дней до окончания SSL» считается относительно жёстко вшитой даты 30.09.2026 11:00, а не текущей даты. Для снимка это допустимо, но подпись должна быть «на 30.09», иначе через неделю документ будет врать.

### 4.8. Что сделано хорошо и стоит сохранить в целевой системе
- Разделение статусов: нарушение / риск / проверить / факт. Старая дата страницы не считается нарушением без доказанного изменения данных.
- Проверка «живости» по телу ответа, а не по коду (сервер отдаёт soft-404 с кодом 200).
- Учёт того, что доступность зависит от IP источника (DDoS-Guard).
- Реестр цифр «значение → источник → дата → метод» и блок дельты между версиями.
- Карточка = норма + где + что делать + ответственный + срок.

- Точная нумерация пунктов ПП №1802 в действующей редакции.

## 6. Итоговая оценка документа
Как отчёт-гипотеза для руководителя документ добротный: внутренне непротиворечив, честно разделяет доказанное и предполагаемое. Как образец выходного документа будущей системы он требует: вычислимых оценок вместо экспертных, блока безопасности и ПДн, машиночитаемого экспорта, исправления ссылки на ч. 3 ст. 29 и одной рукописной цифры.
