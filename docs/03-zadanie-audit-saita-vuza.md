# Задание: аудит официального сайта вуза на соответствие законодательству с выдачей дашборда

Версия 1.0 от 07.10.2026. Задание универсальное для любого вуза России: подставьте параметры из раздела 0 и передайте исполнителю целиком. Всё остальное менять не нужно.

Исполнитель: нейросетевой агент, размещённый в России, с доступом в сеть, возможностью сохранять файлы и выполнять код (Python). Снимок сайта, скриншоты, пробы ссылок и сверки с реестрами исполнитель делает сам по сети. Результат сдаётся в HTML и сопутствующих файлах, PDF не требуется.

## 1. Что должно получиться

Один вопрос заказчика: соответствует ли сайт вуза требованиям законодательства. Один ответ первой строкой дашборда: «Соответствует», «Есть нарушения» или «Есть риски».

Читатель дашборда: проректор по цифровому развитию. После просмотра он должен без пояснений понимать по каждой проблеме три вещи: что именно не так, где именно на сайте (ссылка на страницу, строку или файл плюс скриншот), кто за это отвечает и к какому сроку.

Состав выдачи (раздел 12): файл данных `data.json`, дашборд `index.html` одним файлом, таблица находок `findings.csv`, папка снимка сайта и скриншотов, краткая записка `README.md` о том, что не удалось проверить и почему. PDF не требуется.

## 2. Пять принципов, которые нельзя нарушать

1. **Каждая ошибка ведёт на конкретное место.** Не «в разделе Документы», а ссылка на страницу и номер строки таблицы или имя файла, плюс скриншот с датой. Карточка без ссылки на место и без скриншота не публикуется.
2. **Число без источника не пишется.** Каждая цифра берётся из сохранённого снимка сайта и пересчитывается из него автоматически. Рукописных чисел в тексте нет. Что не удалось получить, помечается «не проверено», а не оценивается.
3. **«Нарушение» ставится только при доказательстве и подтверждённой норме.** Норма должна быть в таблице раздела 3 со статусом «подтверждено». Если нормы нет или она не проверена, максимальный статус «риск».
4. **Что не считается ошибкой и в список не попадает:** рабочая ссылка на официальный источник с верным документом, как бы ни был записан её адрес; оформление и стиль; любое отклонение, которое не мешает читателю или проверяющему получить сведения и не задевает норму. Ошибка это то, что мешает получить сведения или даёт неверные.
5. **«Не проверено» это не нарушение.** Если страница не открылась, файл не скачался, реестр недоступен, проверка получает статус «не проверено» с причиной и остаётся в списке проверок, чтобы заказчик видел: пропущено сознательно.

## 4. Этапы прогона

### Этап 1. Снимок сайта

1. Сохранить главную страницу, страницу `/sveden` и все 14 подразделов (раздел 5): HTML целиком, заголовки ответа, код ответа, время, SHA-256 тела. Сохранить robots.txt, sitemap.xml, страницу «Руководство». Сохранить все таблицы стилей главной страницы, подключённые шрифты и логотип вуза: они нужны для оформления дашборда (раздел 10.1).
2. Сделать скриншот каждой сохранённой страницы целиком с датой и временем в имени файла.
3. Собрать все ссылки с этих страниц и для каждой выполнить запрос. Вердикт по телу ответа, не по коду: сервер может отдавать 200 на несуществующие адреса. Живой документ отдаёт свой тип (PDF, DOCX) и размер; заглушка содержит «Ошибка 404» или «страница не найдена». Скачать все документы раздела (PDF, DOCX и прочие), сохранить с хэшем.
4. Снять сертификат (срок, цепочка), DNS (A, AAAA, SPF, DKIM, DMARC), WHOIS домена (срок оплаты), список поддоменов из crt.sh.
5. Если есть возможность, повторить пробу главной и `/sveden` с другого маршрута (второй провайдер или зарубежный адрес) и записать разницу.
6. Снимок неизменяем. Все дальнейшие шаги работают только с ним. Дата снимка печатается на дашборде рядом с ответом.
7. Ограничения: не более 2 запросов в секунду; заголовок User-Agent с названием аудита и контактом; никаких активных проверок без разрешения из раздела 0.

### Этап 2. Извлечение данных

1. Для каждого подраздела: есть ли страница, точное название, список полей по разделу 5, значение каждого поля или пометка «пусто».
2. Микроразметка: собрать все атрибуты `itemprop` и `itemtype` на каждой странице; сравнить со словарём из методических рекомендаций Рособрнадзора (примеры имён: `fullName`, `shortName`, `regDate`, `address`, `telephone`, `email`, `eduLevel`, `eduCode`, `eduName`, `eduForm`, `learningTerm`, `fio`, `post`, `teachingDiscipline`). Полный словарь берётся из рекомендаций, а не из памяти.
3. Таблицы: каждая таблица сведений разбирается по колонкам; фиксируется число строк, пустые ячейки, объединённые ячейки, наличие выгрузки CSV/XLSX рядом.
4. Документы: формат, размер, есть ли текстовый слой (извлечь текст, не менее 200 символов на страницу), дата документа на первой странице или в метаданных, наличие файла подписи `.sig` или реквизитов электронной подписи.
5. Ссылки на образовательные стандарты: код направления в тексте ссылки, код в имени файла, домен источника, открывается ли файл.
6. Даты обновления страниц, если выводятся.
7. Персональные данные: формы на сайте, ссылка на политику обработки ПДн, внешние счётчики, шрифты, капчи, виджеты; сведения о людях сверх перечня (фото, личные телефоны, биографии).
8. Безопасность (пассивно): заголовки ответа, версии ПО в заголовках, теги `<script>` и `<iframe>` внутри контентных полей (адреса, ФИО, названия), ответ служебных адресов `/admin`, `/.git`, `/.env`, `/backup` только на факт кода 200.

### Этап 3. Проверки

Выполнить каталог раздела 7 полностью. Каждая проверка получает один результат: соответствует, нарушение, риск, проверить, не проверено, факт. Каждый результат кроме «соответствует» порождает карточку по разделу 8 или строку в списке «не проверено» с причиной.

### Этап 4. Ответственные

Назначить ответственного каждой карточке по разделу 6.

### Этап 5. Расчёт и сборка

Посчитать статусы, оценки групп, индекс (раздел 9), собрать дашборд (раздел 10), выполнить самопроверку (раздел 11), сдать выдачу (раздел 12).

|---|---|---|

| 3 | Документы (document) | устав, правила внутреннего распорядка обучающихся и трудового распорядка, коллективный договор, локальные акты, правила приёма, отчёт о самообследовании до 20 апреля |
| 4 | Образование (education) | по каждой программе: уровень, код, название, форма, срок, дисциплины и практики, численность, аккредитация по реестру (с 01.03.2026 здесь) |

## 6. Назначение ответственных

Правило: ответственный определяется автоматически. Это должность и ФИО со страницы «Руководство» проверяемого сайта на дату снимка, подобранные по таблице ниже. Исполнитель сохраняет страницу «Руководство» в снимке и указывает в карточке, из какой строки взят ответственный. Если подходящей должности на странице нет, пишется типовая должность из таблицы и пометка «ФИО на сайте не найдено»; такая карточка публикуется, а список таких случаев выносится в `README.md`. Если ответственных по профилю несколько, берётся первый по порядку на странице, остальные перечисляются через точку с запятой.

| Группа проблем | Типовой ответственный | Как найти на сайте |
|---|---|---|
| Содержание подразделов: образование, стандарты, педсостав, вакантные места, платные услуги | проректор по учебной работе | «Руководство», должность содержит «учебн» |
| Руководство, структура, кадры, педсостав (кадровые сведения) | проректор по кадрам или по управлению персоналом | должность содержит «кадр» или «персонал» |
| Стипендии, общежития, питание, доступная среда | проректор по социальной или воспитательной работе | должность содержит «социальн» или «воспитат» |
| Финансы, платное обучение (стоимость) | проректор по экономике или финансам | должность содержит «эконом» или «финанс» |
| Международное сотрудничество | проректор по международной деятельности | должность содержит «международн» |
| Документы, локальные акты, устав | учёный секретарь или юридическое управление | должность содержит «секретар» или «юрид» |
| Всё техническое: шаблон страниц, доступность, сертификат, домен, безопасность, микроразметка, выгрузки, скрытые документы, мусор в данных, скорость | проректор по цифровому развитию или начальник управления информатизации | должность содержит «цифров» или «информ» |
| Филиалы | директор филиала плюс технический ответственный головного вуза | сайт филиала, страница «Руководство» |

Срок в карточке всегда дата. Ориентиры: признак взлома 3 дня; истекающий сертификат или домен до даты истечения; нарушение новой нормы с истёкшим сроком 3 недели; остальные нарушения до конца следующего месяца; риски 2 месяца; «проверить» 2 недели; факты квартал.

## 8. Карточка ошибки

Каждая карточка содержит ровно эти поля. Карточка без любого из первых четырёх не публикуется.

| Поле | Требование | Пример |
|---|---|---|
| Что не так | одна фраза без терминов, понятная ректору | Ссылка на стандарт 37.04.01 открывает стандарт другого направления |
| Где | кликабельная ссылка на страницу плюс строка таблицы, якорь или имя файла | страница «Образовательные стандарты», строка 118 |
| Скриншот | файл с датой и временем из снимка, выделено место ошибки | `shots/eduStandarts_ГГГГ-ММ-ДД_ЧЧММ_row118.png` |
| Доказательство | что именно найдено в снимке, какими данными | в тексте ссылки код 37.04.01, файл 380401.pdf |
| Источник | снимок (дата), проба (дата), реестр (название, дата) | снимок ДД.ММ.ГГГГ |
| Статус | нарушение, риск, проверить, факт | нарушение |
| Норма | акт, пункт, одна строка сути, из таблицы раздела 3 | ч. 1 ст. 29 ФЗ-273; п. 15 Требований №1493 |
| Что сделать | конкретное действие, закрывающее ошибку | заменить ссылку на файл стандарта 37.04.01 из реестра fgosvo.ru |
| Кто | должность и ФИО по разделу 6 | проректор по учебной работе, Фамилия И.О. |
| Срок | дата | до ДД.ММ.ГГГГ |
| Построчно | если ошибок одного типа много, список внутри карточки, каждая строка со ссылкой | 4 строки |
| Обнаружено | дата снимка | ДД.ММ.ГГГГ |

Правила формулировок: одна карточка одна ошибка; «что не так» пишется так, чтобы понять без юриста и без айтишника; «что сделать» это действие, а не пожелание; если сайт закрыт для внешних адресов, скриншот обязателен вдвойне.

## 9. Статусы, веса, индекс

| Статус | Когда ставится | Вес |
|---|---|---|
| Нарушение | есть доказательство и подтверждённая норма | 1,0 |
| Риск | косвенный признак, или норма со статусом «сверить», или отклонение от формы без потери сведений | 0,5 |
| Проверить | нужны данные вуза или дополнительная проба | 0,2 |
| Не проверено | проверка не выполнена, причина указана | 0,2 |
| Факт | справочно, нормы не касается | 0 |
| Соответствует | проверено, нарушений нет | 0 |

Оценка группы: `S_g = 100 × (1 − Σ min(вес статуса, вес класса) / Σ вес класса)` по всем проверкам группы. Вес класса: нарушение 1,0; риск 0,5; проверить 0,2; факт 0.

Индекс: `I = 0,40·S_А + 0,15·S_Б + 0,15·S_В + 0,15·S_Г + 0,15·S_Д`. Группа Е не входит.

Главный ответ: «Есть нарушения», если хотя бы одна карточка со статусом «нарушение»; иначе «Есть риски», если есть риск или не проверено; иначе «Соответствует». Индекс ответ не заменяет: при одном нарушении и индексе 95 ответ всё равно «Есть нарушения».

## 10. Дашборд

Один файл `index.html`, открывается с телефона и без JavaScript (содержимое пререндерено, скрипты только для фильтров и раскрытия). Все числа на странице берутся из `data.json`. Три экрана в фиксированном порядке.

### Экран 1. Ответ

1. Шапка: название вуза, домен, номер сборки, дата снимка, дата проб, редакция правил.
2. Вердикт цветом: красный «Есть нарушения», жёлтый «Есть риски», зелёный «Соответствует». Под ним дата снимка.
3. Три числа: нарушения, риски, не проверено.
4. Три принципа (из раздела 2, пункты 1–3) одной строкой каждый.
5. Фильтры по статусу с количеством, кнопка «Раскрыть все карточки».
6. Список ошибок по убыванию важности: статус, что не так, где (ссылка), кто, срок, кнопка «Подробнее». Кнопка открывает карточку по разделу 8 прямо под строкой, включая построчный список и скриншот.
7. На телефоне список превращается в карточки: статус и кнопка в первой строке, ниже заголовок и подписи «Где», «Кто», «Срок».

### Экран 2. Общая аналитика

1. График «Находки по 14 подразделам»: горизонтальные полосы, сегменты нарушения, риски, проверить; нажатие фильтрует экран 1.
2. Индекс соответствия крупно и оценки пяти групп с весами.
3. Таблица подразделов: подраздел (ссылка на сайт), колонка «Что не так» со списком проблем подраздела (каждая ведёт в свою карточку), число нарушений, рисков, проверить, число файлов, дней без обновления. Подраздел без проблем подписан «проблем не найдено».
4. Доля машиночитаемых таблиц и документов.
5. Два блока, если данных нет, с пометкой «не входит в эту сборку»: «Как увидит проверяющий», «Вуз среди соседей».

### Экран 3. Подробности

1. Все проверки каталога с результатом, классом, способом и примечанием; фильтр по результату; у «не проверено» обязательна причина.
2. Реестр цифр: каждое число отчёта, источник, дата, метод.
3. Экспорт: текст CSV и JSON находок с кнопкой копирования; ссылка на `findings.csv`.

Требования к сборке: оформление по токенам проверяемого сайта (раздел 10.1); шрифты с запасным системным; тёмная тема; непроверенное серым; дата снимка из данных, а не текущая; нет горизонтальной прокрутки на ширине 390 пикселей; скриншоты встроены или лежат рядом в папке `shots/` и открываются по ссылке из карточки.

### 10.1. Оформление: дизайн-токены берутся с проверяемого сайта

Дашборд оформляется в фирменном стиле проверяемого вуза, чтобы читался как его внутренний документ, а не как чужой отчёт. Токены извлекаются из снимка главной страницы автоматически и записываются в `data.json` в блок `meta.design`.

| Токен | Откуда взять | Правило |
|---|---|---|
| `brand_primary` | основной цвет шапки, меню или кнопок главной страницы (самый частый насыщенный цвет в стилях) | используется для акцентов, ссылок и заливки индекса |
| `brand_secondary` | второй по частоте фирменный цвет | используется для подзаголовков и рамок |
| `background` | фон страниц сайта | фон дашборда; если фон сайта тёмный, дашборд делается тёмным |
| `font_heading` | шрифт заголовков из стилей сайта | заголовки дашборда; если шрифт не загружается, запасной системный |
| `font_body` | шрифт основного текста сайта | текст дашборда |
| `logo` | логотип вуза с главной страницы, сохранён в снимке | в шапке дашборда рядом с названием вуза, высота не более 48 пикселей |
| `radius` | скругление кнопок и карточек сайта | скругление карточек дашборда |

Что не берётся с сайта: цвета статусов. Красный «нарушение», жёлтый «риск», синий «проверить», серый «не проверено», зелёный «соответствует» фиксированы и одинаковы для всех вузов, чтобы вердикт читался одинаково. Если фирменный цвет вуза совпадает с одним из цветов статусов, фирменный цвет используется только в шапке.

Проверки после извлечения: контраст текста на фоне не ниже 4,5:1, иначе цвет затемняется или осветляется до нормы с пометкой в `README.md`; тёмная тема строится из тех же токенов. Если стили сайта извлечь не удалось, применяется нейтральная палитра, а в `README.md` указывается причина. Сами извлечённые значения и адреса файлов стилей записываются в реестр цифр как источник оформления.

## 11. Самопроверка перед сдачей

Исполнитель отвечает на каждый вопрос «да» и прикладывает ответы в `README.md`. Любое «нет» означает, что сдавать нельзя.

1. У каждой карточки есть ссылка на конкретное место, скриншот, норма из таблицы раздела 3, ответственный с должностью и ФИО, срок датой.
2. Каждое число на дашборде есть в `data.json` и в реестре цифр с источником и датой; рукописных чисел в тексте нет.
3. Каждое «нарушение» опирается на норму со статусом «подтверждено».
4. Ни одна карточка не описывает «не-ошибку» из принципа 4: рабочие ссылки с некрасивым адресом, отсутствие необязательных элементов (выгрузка CSV, файл подписи, дата обновления) не выводятся как ошибки.
5. Все проверки каталога присутствуют в списке с результатом; у каждого «не проверено» указана причина.
6. Индекс и оценки групп пересчитываются вручную из `data.json` по формулам раздела 9 за 10 минут и совпадают с дашбордом.
7. Одна карточка одна ошибка; составные карточки разделены.
8. «Что не так» читается без юриста и айтишника; «что сделать» это действие.
9. Дашборд открывается с телефона и без JavaScript, горизонтальной прокрутки нет.
10. Ничего не отправлялось на сайт кроме GET-запросов; активные проверки не выполнялись без разрешения.
11. Оформление дашборда построено на токенах проверяемого сайта по разделу 10.1, цвета статусов не изменены, контраст текста не ниже 4,5:1.

Рекомендуется второй прогон другим агентом или человеком по этому списку до сдачи.

## 13. Что делать, если

- Сайт не открывается с адреса исполнителя: записать код и текст ответа, попробовать второй маршрут; если недоступен везде, выдать дашборд с ответом «Есть риски», одной карточкой «сайт недоступен» и всеми проверками «не проверено».
- Страница «Руководство» не даёт ФИО по должности: ответственный пишется должностью с пометкой «ФИО уточнить у заказчика».
- Норма изменилась после даты задания: добавить в таблицу раздела 3 с датой вступления и применить, если дата снимка позже.
- Данных для проверки нет в снимке и получить их нельзя: «не проверено» с причиной, не оценивать.
- Найден признак взлома (чужой код в контенте, домен в чёрном списке): карточка со сроком 3 дня и отдельное уведомление заказчику в первой строке `README.md`.
